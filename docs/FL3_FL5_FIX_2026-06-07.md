# FL3 + FL5 Fix Notes - 2026-06-07

## Scope

- FL3: Cloud login returned to the home page after sign-in instead of the dashboard/app.
- FL5: Brain upload rejected a 1.4 MB image with raw "Request body too large" and first upload was flaky when no folder existed.

## FL3 Root Cause

The FastAPI `/auth/login` route created a `wos_session` cookie, but the Next proxy did not forward upstream `Set-Cookie` back to the browser. A login page posting through `/api/proxy/auth/login` could receive a 200 response while the browser never persisted the session. The web app also had no tracked `/auth/login` page in this checkout, so the login copy and post-login target were implicit.

## FL3 Fix

- `apps/web/app/api/proxy/[...path]/route.ts` now forwards request cookies/auth headers upstream and forwards upstream `Set-Cookie` downstream.
- `POST /auth/login` now returns `redirect_to: "/overview"` on success.
- `apps/web/app/auth/login/page.tsx` adds a real login screen.
- Confirmed login copy: **"Sign in to your Workeros workspace"** with supporting text **"Use the username and password for this workspace."**
- Successful login navigates to a safe local `return_to` path or `/overview`.

## FL5 Root Cause

The API's generic `/uploads` route already defaulted to 25 MB, but Brain files use `/contexts/{name}/upload`. The Next proxy streamed only exact `/uploads`, so Brain uploads were buffered through `req.arrayBuffer()`. The backend also had no Brain-specific friendly 413 response, and missing folders only auto-created when the client explicitly sent `create_if_missing=true`.

## FL5 Fix

- `/contexts/{name}/upload` is treated as a streaming upload path in the Next proxy.
- Brain uploads now default to a 25 MB file limit via `WORKEROS_CONTEXT_UPLOAD_MAX_BYTES`.
- Oversized Brain uploads return friendly 413 JSON: `Brain upload is too large. Upload files up to 25 MB.`
- Generic body-limit 413s no longer emit raw `Request body too large`.
- Missing Brain folders auto-create by default on upload.
- The Brain UI creates a new user folder when the only selected item is missing, system-owned, or read-only.
