# Workeros v1.0.0 - Initial Source-Available Release

Workeros v1.0.0 is the first public release of the self-hosted runtime for AI
workers. It is published as a clean source-available release with useful
development history preserved and private/internal artifacts filtered out.

The public repo contains the source, docs, tests, and examples that users should
install, inspect, fork, and build on.

## Highlights

- FastAPI backend for workers, runs, connections, approvals, contexts, users,
  tokens, and operational views.
- Next.js web app for creating, running, monitoring, and sharing workers.
- MCP and CLI package published as `@floomhq/workeros`.
- E2B-sandboxed worker execution by default.
- Script workers with deterministic `run.py` contracts.
- Agent workers with `SKILL.md`, tool loops, limits, transcripts, and outputs.
- Manual, cron schedule, webhook, and Composio-triggered worker runs.
- Composio OAuth connection support with server-side tool proxying.
- Human approval flows for side-effecting automation.
- Run logs, artifacts, bundles, replay metadata, and public/share-link views.
- Context packs for reusable worker reference material.
- Git-backed workspace export/versioning when configured outside the engine
  source checkout.
- Seed workers for Gmail, GitHub, Slack, WhatsApp, worker authoring, and
  workspace operations.

## Security Posture

- Workers run in E2B sandboxes, not inside the API process.
- Platform secrets remain on the server side.
- Sandboxes call scoped API proxy endpoints with run-scoped tokens.
- Connection declarations and allowed tool lists are explicit in `worker.yml`.
- Uploads, bundles, paths, markdown rendering, redirects, proxy settings,
  webhook delivery, and token surfaces have dedicated validation and tests.
- `.env` files, local SQLite databases, artifacts, and generated runtime data are
  excluded from the source tree.

## Known Limits

- Worker execution requires E2B credentials.
- Local setup requires a configured model provider key.
- Composio event triggers require `COMPOSIO_WEBHOOK_SIGNING_KEY` and a reachable
  webhook URL.
- E2B warm pools are available behind environment flags, but should be sized
  conservatively because warm sandboxes are still running compute.
- The public issue tracker starts curated. Historical internal issues are not
  imported wholesale.

## Upgrade And Compatibility

This is the first public release, so there is no public upgrade path from an
earlier public version. Operators running an internal or private build should treat
this as a source-available v1.0 release and compare local configuration carefully before
moving data.
