## P0 - Cloud Magic-Link Email Corruption

### Root Cause

Cloud Supabase Auth emails were generated by `scripts/configure_supabase_auth_emails.py` with a raw token query separator:

```text
token_hash={{ .TokenHash }}
```

The live emails are sent as quoted-printable via SES. When a token hash begins with bytes that look like quoted-printable escapes, for example `e9` or `cb`, the raw `=` before the token can be decoded as part of the transfer encoding. The UX walk observed exactly that failure mode: the email body arrived with the `token_hash=` separator damaged, so `/auth/callback` received a malformed query and authentication failed.

### Fix

Cloud PR #113 updates the Supabase Auth email template to avoid raw `token_hash=XX` sequences and updates `apps/api/routes/auth.py` to parse QP-safe emitted forms:

- direct callback query parts like `token_hash%3D...` and `type%3Dsignup`
- nested `confirmation_url` callback values containing the same encoded separators

## P1 - OSS Assistant Base Editor 404

### Root Cause

The `/assistant` page loaded three resources together:

- `/system/workspace-agent`
- `/workspace/base/state`
- `/workspace`

The deployed OSS API currently returns:

- `GET /workspace/base/state` -> HTTP 404 `{"detail":"Not Found"}`
- `GET /workspace/base` -> HTTP 200 with the resolved Emily base persona

Because `/workspace/base/state` rejected the `Promise.all`, the page displayed "Couldn't load the assistant - Not Found" and left the base-instructions editor empty even though the current base persona was available from `/workspace/base`.

### Fix

`apps/web/lib/api.ts` now falls back to `GET /workspace/base` when `GET /workspace/base/state` returns `Not Found`. The fallback returns:

```json
{
  "content": "<resolved /workspace/base markdown>",
  "is_custom": false,
  "default": "<same resolved markdown>"
}
```

This keeps the editor populated on the current live API and preserves the richer state endpoint when it is available.
