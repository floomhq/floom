## P2 / nitpicks / known-future

- Artifact dirs not cleaned from disk on /runs/clear or worker delete (disk leak)
- Cloudflare WAF blocks /health from AX41 IPv6 unauth (monitoring concern)
- E2B sandbox allows outbound network egress (design — workers need to call APIs; verified platform secrets do NOT leak)
- Source code disclosure via `GET /workers/{id}` returning `run_py_content` (intentional for single-user; for v1, owner-scoped)
- No backup of runs/artifacts (no rollback after destructive operations)
- No metrics endpoint, no monitoring

## What works well (don't break)

- E2B sandbox isolation (zero platform-key env leak, runs as unprivileged user, killed after execution)
- Auth: every authed endpoint returns 401/403 without secret; case-insensitive header handled
- Cloudflare WAF blocks unauthenticated traffic
- Path traversal blocked (B3, C1-C3 from security audit)
- Rate limiting (200 req/min per secret-hash; verified)
- OWASP security headers (HSTS, X-Frame, CSP, Permissions, X-CTO, Referrer-Policy)
- Sandbox lifecycle: spawned per-run, killed after, no persistence between runs
- Run detail page with millisecond timeline + artifact downloads (UI/UX praised this)
- Visual cron builder (PR J) beats Zapier's
- Prompt-to-worker generation (when it works) is genuinely novel
- Example chips on /workers/new are well-designed UX
- Real Floom logo + tabs on /workers/[id] + sticky sidebar + top filter bar all clean

## Reconciliation: external auditor's 22/100 and revised 48/100

- The original 22/100 score was based on a misconfigured local dev server (port 8000, in-process executor that doesn't exist on main). Findings did not apply to production. Documented in ARCHITECTURE.md so this can't recur.
- The revised 48/100 against production found 3 real P0s (now all fixed) plus the secrets-disclosure / paths-disclosure findings that are acceptable for v0 single-user but need attention for v1 multi-tenant.
- Where the external auditor agreed with our own audits: secrets isolation in E2B (correct, verified false-positive on os.environ; FIXED for secrets.json too), /runs/clear footgun (FIXED), runner:local schema accepted (FIXED).
- Where they over-claimed: the May 26 22/100 sandbox-escape findings (route injection, env poisoning) — those required in-process execution which doesn't exist.
- Where they correctly added new findings: /system/info disclosure (acceptable v0, queued for v1), no rate limiting on /runs/clear (FIXED indirectly via confirm-token requirement).

2. **Audit prompts MUST point at `https://workers-api.floom.dev`**, never localhost or a cloned repo's local uvicorn.
3. **Virgin VPS audit environment** (the operator's request): for future audits, provision a separate Hetzner VPS with a copy of the workeros codebase + E2B credentials + a throwaway `FLOOM_SECRET`. Future audits write to docs/audits/<vps-id>-<date>.md.
4. **Rotate `FLOOM_SECRET` after any external audit** (already promised; do it now).
5. **No external auditor gets full admin secret** — give them a token scoped to read-only endpoints (when multi-tenant ships in v1) or a virgin-VPS-scoped secret that only sees the audit DB.
