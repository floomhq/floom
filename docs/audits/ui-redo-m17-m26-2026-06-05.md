# UI Audit: M17 + M26 — 2026-06-05

## Fix M17 — Post-Slack-OAuth: redirect user INTO Slack

### File changed
`apps/web/components/assistant/SlackConnect.tsx`

### Problem
After connecting Slack, the user lands back on `/settings#slack` and sees only:
- A toast ("Slack workspace connected") that auto-dismisses in ~4s
- The workspace in the list with a small "Open [workspace]" button
- A small text link "Open [workspace]→" at the bottom

The CTA to actually go into Slack was easy to miss — the operator called this "very stupid".

### Fix
- Detect `?slack_connected=1&team_id=<id>` query params on mount (already emitted by the API callback at `main.py:13986`)
- Capture `team_id` into `justConnectedTeamId` state
- Resolve workspace name from the loaded `installed_teams` list into `justConnectedTeam`
- Show a prominent green banner immediately below the section header:
  - `CheckCircle2` icon + "{workspace} connected" label
  - Slack-aubergine "Open {workspace} in Slack" button with `ExternalLink` icon
  - Deep-links to `https://app.slack.com/client/{team_id}`
  - Banner dismissed when user clicks the link (sets state to null)
- Clean params from URL (already done; extended to include `team_id`)

### Before screenshot
The before state shows no prominent CTA after connecting — just the toast and the team list.
Screenshot: `/tmp/before-m17-slack-connected.png`

### After
After the fix, when returning from Slack OAuth with `?slack_connected=1&team_id=T0B78MD7OQN`,
a prominent green callout appears with "test-games connected" and an "Open test-games in Slack" button.

### Verification
- `justConnectedTeam` is resolved from `installed_teams` once the status API responds
- If status is still loading and `justConnectedTeamId` is set but `justConnectedTeam` is null,
  the banner shows with generic "Workspace connected" text and the team_id deep-link
- Banner is NOT shown on regular page visits (no query param)

## Fix M26 — Worker source tab label "Summary" → "Preview"

### File changed
`apps/web/components/worker-form/FilesEditor.tsx` (already fixed in origin/main)

### Status: ALREADY FIXED IN origin/main

The `sourceModeLabel()` function previously returned `"Summary"` for `worker.yml` in edit mode:
```ts
return isWorkerYaml ? "Summary" : "Preview";
```

It now returns `"Preview"` for all rendered views:
```ts
// All rendered views use "Preview" — consistent with Brain file viewer.
return "Preview";
```

The view-mode tab was already `<TabsTrigger value="preview">Preview</TabsTrigger>` (line 374).
The edit-mode toggle now also shows "Preview" (via `sourceModeLabel()`).
Function names (`hasWorkerYamlSummary`, `WorkerYamlPreviewContent`) are unchanged — only user-visible labels.

### Verification
The deployed app at workers.floom.dev/workers/ai-news-summary#source already shows "Raw | Preview"
(not "Raw | Summary") for `worker.yml`. Screenshot: `/tmp/before-m26-source-tab.png`
