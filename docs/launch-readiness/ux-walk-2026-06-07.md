# Workeros Launch-Readiness — UX/Functional Walk (2026-06-07)

**Scope:** UX half of the launch-readiness audit (a separate Codex lane owns backend/security).
Live skeptical-user walk of the synced build.

**Targets:**
- OSS app — `https://workers.floom.dev` (single-user, access-secret auth)
- Cloud — `https://workeros.floom.dev` (multi-member login, hosted)

**Method:** AX41 Browser Broker (leased pool-b, released; audit score 85, 0 raw-CDP bypass) for authed desktop walk; gstack `/browse` for anonymous mobile spot-checks. Every surface screenshotted; console/HTTP behavior noted. Screenshots under `/tmp/lr-ux-walk/`.

---

## Overall UX Score: 81 / 100

The OSS app is genuinely strong: clean dark+light themes, employee-card framing, a working tool-detector, output-first run views, and a verified chat-persistence feature. The Cloud marketing surface is polished and on-brand. Two real functional defects pull the number down hard from the ~90 the visual craft alone would earn:

- **P0:** Cloud magic-link / email-confirmation URL is corrupted in the email itself (`token_hash=` separator destroyed by quoted-printable encoding) — email signup is broken for every new Cloud user. Reproduced twice.
- **P1:** OSS `/assistant` base-instructions editor surfaces a "Couldn't load the assistant — Not Found" error and loads no content.

Visual/UX+a11y craft alone: ~11/12. Functional correctness on NEW features: dragged down by the two defects above.

## Branding cross-check ("Floom should be gone")

- **OSS app UI:** clean — logo/nav/pages say **Workeros**; CLI binary is `workeros`. Only *infra* Floom strings remain in the Developer tab copy (`x-floom-secret` header name, `floom_` PAT prefix, `@floomhq/workeros` npm pkg, `*.floom.dev` domains). These are real infra identifiers — needs Federico's call, not auto-fix. (P2)
- **Cloud:** intentionally Floom-attributed ("Workeros BY FLOOM", footer © 2026 Floom, Floom Skills links). This is by-design corporate attribution, NOT a regression.
- **Cloud inconsistencies (P2):** login card says **"Sign in to Floom"** and tab title **"Sign in · Floom"** on a product called Workeros; landing "EVERY RUN ON THE RECORD" body copy reads **"Floom shows the trigger…"** (should be "Workeros shows…"); confirmation email is all-Floom ("finish setting up your Floom account").

## Ranked findings

### P0 (launch blocker)
1. **Cloud magic-link email URL corrupted — email signup broken.** The `token_hash=` separator is destroyed by quoted-printable encoding in the auth email template (`=` collides with QP escaping; `=e9`→dropped, `=cb`→`\x17`). Real users clicking "Confirm email" send a malformed query with no `token_hash` value → callback 401. Reproduced twice (`auth@floom.dev`, sender via SES/links.floom.dev). Fix: encode the URL so `=` and following hex aren't QP-mangled (e.g. send the link as a non-QP part, or URL-encode `=` / break the hex-after-`=` pattern). Verify by clicking a freshly-issued link end-to-end into `/app`.

### P1
2. **OSS `/assistant` base-instructions editor: "Couldn't load the assistant — Not Found".** NEW feature surfaces an error and loads no content; the editor scaffold renders but the base-instructions textarea is empty. Backend `GET` for the assistant config 404s. Needs the assistant config to load (and a non-error empty/seed state).

### P2
3. Runs list column headers collide ("Worker"/"Trigger" → "WoTrigger") at default width.
4. OSS 404 is the bare Next.js default — add branded copy + "back to Overview" CTA.
5. Cloud login/title say "Sign in to Floom" / "Sign in · Floom" — inconsistent with Workeros product name.
6. Cloud landing copy: "Floom shows the trigger…" should read "Workeros shows…".
7. Cloud confirmation email copy is all-Floom ("your Floom account") — align with Workeros if intended.
8. OSS Developer-tab infra strings (`x-floom-secret`, `floom_` PAT prefix) — decide whether to rebrand.
9. Theme toggle doesn't persist as Light across navigation (reverts to System).

### Could not verify (tooling/auth limits, flagged honestly)
- Connections animated "Connecting" state (all test apps already connected; fresh OAuth would junk prod).
- Authed Cloud app + workspace-actions submenu + light-mode highlight (blocked by P0 magic-link break; OAuth needs Federico).
- Authed-page mobile spot-check (broker fixed-width; raw-Playwright resize hook-blocked; gstack anonymous-only).
